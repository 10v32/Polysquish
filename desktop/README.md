# Polysquish desktop

A native window around the Polysquish web UI. The app starts the regular Polysquish HTTP server
**in-process** on a random loopback port (`127.0.0.1:0`) and shows it in the system WebView:

| Platform | WebView            | Window toolkit |
|----------|--------------------|----------------|
| Windows  | WebView2 (Edge)    | Win32 via `tao` |
| macOS    | WKWebView          | AppKit via `tao` |
| Linux    | WebKitGTK 4.1      | GTK 3 via `tao` |

The crate is `polysquish-desktop` (binary name `Polysquish`); it depends on the root `polysquish`
crate by path and uses `polysquish::server::serve_with_ready` to learn which port was bound.
Nothing else changes: the CLI binary `polysquish` (`polysquish ui`, `polysquish squish`, ...) is
still built and released separately by `.github/workflows/build.yml`.

## Run in development

```sh
cargo run -p polysquish-desktop
```

The window is 1280x820 (minimum 900x600), titled "Polysquish", with a `#0b0716` background so it
never flashes white while the page loads. Closing the window exits the process and with it the
embedded server. Links to anything that is not `127.0.0.1`/`localhost` open in your default
browser instead of inside the app. File drag-and-drop is handled by the web UI itself.

The app icon is generated procedurally by `build.rs` (a pink-to-purple blob like the UI logo):
`desktop/icons/icon.png` (512x512), `desktop/icons/icon.ico` (16..256 px, embedded into the
Windows executable via `embed-resource`), and a raw 256x256 RGBA copy used as the runtime window
icon. The `icons/` folder is git-ignored; it appears after the first build.

## Prerequisites

* **Linux**: `sudo apt-get install -y libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev`
  (Fedora: `webkit2gtk4.1-devel gtk3-devel`). The resulting binary and the AppImage link
  dynamically against WebKitGTK 4.1, so end users need `libwebkit2gtk-4.1` installed too.
* **macOS**: Xcode command line tools. `iconutil`, `sips`, `codesign` and `hdiutil` ship with
  macOS and are only needed for packaging.
* **Windows**: the MSVC toolchain (Visual Studio Build Tools, which provide `rc.exe` for the icon
  resource). End users need the WebView2 runtime, which is preinstalled on Windows 10/11.

## Where things go

* **Squished models**: `<Documents>/Polysquish` (falls back to `$HOME/Polysquish`), the same
  default as `polysquish ui`. The UI shows the exact folder for each job.
* **Temporary uploads/work files**: `<temp dir>/polysquish-<pid>`, removed when the server shuts
  down cleanly.
* **Build output**: `target/debug/Polysquish` (or `target/release/Polysquish`); the generated
  icons land in `desktop/icons/`.

## Installers (CI)

`.github/workflows/desktop.yml` builds release binaries on every push and attaches installers
to GitHub releases for `v*` tags:

| Artifact | Contents |
|----------|----------|
| `Polysquish-x86_64.AppImage` | Linux AppImage built with `appimagetool` from `packaging/polysquish.desktop` + the generated icon. `chmod +x` and run. |
| `Polysquish-arm64.dmg`, `Polysquish-x86_64.dmg` | `Polysquish.app` (`packaging/Info.plist`, bundle id `app.polysquish.desktop`, `.icns` from `iconutil`) in a drag-to-Applications disk image made with `hdiutil`. The app is only ad-hoc signed, so on first launch right-click > Open (or allow it under System Settings > Privacy & Security). |
| `Polysquish-windows-x86_64.zip` | The bare `Polysquish.exe`; unzip anywhere and run. |
| `Polysquish-x86_64.msi` | **Best effort.** Produced with `cargo-wix` when it installs within 15 minutes and the WiX v3 toolset is available on the runner. If that step fails the workflow still succeeds and only the zip is published. The MSI's upgrade code is regenerated by `cargo wix init` on each run, so treat each MSI as a fresh install rather than an in-place upgrade. |

## Known limitations

* No native menu bar yet. On macOS that means Cmd+Q and the Edit-menu shortcuts are not wired
  up; close the window to quit.
* Windows release builds hide the console (`windows_subsystem = "windows"`); debug builds keep
  it so server logs stay visible.
